## 2. 项目背景与应用场景

### 背景

随着智能手机的普及，校园课堂中学生在课上使用手机的现象日益严重，影响教学秩序和学习效果。传统的人工巡查方式效率低、覆盖面有限，难以实现全天候、全场景的监控。计算机视觉技术（特别是目标检测）为自动化校园手机使用行为识别提供了可行方案。

### 应用场景

1. **课堂教学辅助**：教师上传课堂照片，系统自动检测是否有学生在用手机
2. **考试监考辅助**：识别考场中出现的手机设备
3. **校园安全管理**：监控公共区域手机使用行为，辅助校园秩序管理

### 为什么这是一个有价值的应用

- 教育场景真实需求，有明确应用价值
- 目标检测技术成熟，可落地性强
- 为校园智能化管理提供技术支撑

## 3. 任务类型

**目标检测 (Object Detection)**：对输入的校园场景图片进行自动分析，检测出"使用手机的人 (People using cellphone)"和"手机 (cellphone)"两类目标，输出检测框位置、类别和置信度。

---

## 4. 输入输出说明

### 输入

- **类型**：JPG / PNG 格式校园场景图片
- **分辨率**：自动适配训练尺寸 640×640
- **来源**：Roboflow Smart School v5 数据集（训练），用户上传图片（推理）

### 输出

- **检测框列表**：每个检测框包含类别、置信度、位置坐标 (x1, y1, x2, y2)
- **统计报告**：各类别数量、平均置信度、检测明细
- **标注图片**：在原图上绘制检测框和标签

## 5. 模型与技术路线

### 技术路线

采用 **YOLO11**（You Only Look Once 第 11 代）作为核心检测模型。YOLO 系列是单阶段目标检测器的代表，在速度与精度之间取得了优秀的平衡。

### 模型选择理由

| 对比维度 | YOLO11 | Faster R-CNN | RT-DETR |
|---------|--------|-------------|---------|
| 检测速度 | 最快（单阶段） | 较慢（两阶段） | 中等 |
| 精度 | 高 | 高 | 很高 |
| 训练难度 | 简单（ultralytics 封装） | 中等 | 中等 |
| 数据增强 | 内置丰富增强 | 需手动配置 | 有限 |
| 部署便利性 | 一站式训练/导出/部署 | 较复杂 | 中等 |

**选择 YOLO11 的核心理由**：
1. ultralytics 框架提供完整的训练/验证/推理/导出 Pipeline，减少工程代码量
2. 内置 Mosaic、HSV、翻转等数据增强，适合 141 张小样本数据集
3. 提供 nano/small/medium 多个变体，便于多组实验对比

### 数据增强策略

| 增强方式 | 参数 | 作用 |
|---------|------|------|
| Mosaic 拼接 | 1.0 (开启) | 4 张图拼 1 张，丰富背景 |
| HSV 抖动 | h=0.015, s=0.7, v=0.4 | 色彩变化，提升光照鲁棒性 |
| 水平翻转 | 0.5 | 对称扩充 |
| 尺度缩放 | 0.5 | 多尺度训练 |
| 平移 | 0.1 | 位置变化 |

## 9. 项目实现过程

### 阶段一：方案分析与重构决策

- 分析旧项目（CLIP+BLIP-2 图文检索）存在的根本问题：YOLO 目标检测标注被强行用于检索任务，Recall@5 仅 0.0065
- 确定重建为 YOLO11 目标检测项目，确保"任务-数据"匹配

### 阶段二：基础设施搭建

- 备份旧项目 → 创建新目录结构 → 重写 requirements.txt
- 实现 7 个核心模块：数据准备 (dataset.py)、训练脚本 (train.py)、推理检测 (detect.py)、Web 前端 (app.py)、工具函数 (helpers.py + metrics.py)
- 编写 6 类冒烟测试

### 阶段三：第一轮训练实验（Smart School v5, 141 张）

- exp0 (yolo11n, 100 epochs): mAP@50=0.30
- exp1 (yolo11s, 100 epochs): mAP@50=0.29
- exp2 (yolo11m, 150 epochs): mAP@50=0.25 — 大模型反而更差，过拟合
- **关键发现**：数据量太小，模型规模和数据增强无法弥补

### 阶段四：数据集重组

- 从 Roboflow 下载 University-Outdoor、University ver 2/3、School v1 共 4 个额外数据集
- 编写 merge_datasets.py 统一类别映射（person→person, cellphone→phone 等），生成重组数据集
- 最终数据集规模显著增加，涵盖更多校园场景

### 阶段五：第二轮训练实验（重组数据集）

- exp3 (yolo11n, 早停 61/100 epochs): mAP@50=**0.73**, mAP@50-95=**0.50**
- exp4 (yolo11s, 100 epochs): mAP@50=**0.73**, mAP@50-95=**0.51**, Recall=**0.88**
- exp5 (yolo11m): 训练中断，未完成
- **关键成果**：mAP@50 从 0.30 跃升到 0.73，成功达到 0.70 质量目标

### 阶段六：Harness 文档与最终报告

- 重写全部 11 个 Harness 文档
- 填写最终报告 16 个部分
- 整理实验数据、代码和文档准备提交

## 11. 结果展示与分析

### 实验对比表

#### 第一阶段：原始 Smart School v5 数据集 (141 张)

| 实验 | 模型 | Epochs | mAP@50 | mAP@50-95 | Precision | Recall |
|------|------|--------|--------|-----------|-----------|--------|
| exp0 | YOLO11n | 100 | 0.30 | 0.13 | 0.48 | 0.27 |
| exp1 | YOLO11s | 100 | 0.29 | 0.16 | 0.57 | 0.26 |
| exp2 | YOLO11m | 150 | 0.25 | 0.13 | 0.50 | 0.25 |

#### 第二阶段：多数据集重组后

| 实验 | 模型 | Epochs | mAP@50 | mAP@50-95 | Precision | Recall |
|------|------|--------|--------|-----------|-----------|--------|
| exp3 | YOLO11n | 61 (早停) | **0.73** | **0.50** | 0.72 | 0.86 |
| exp4 | YOLO11s | 100 | **0.73** | **0.51** | 0.72 | 0.88 |
| exp5 | YOLO11m | 训练中断 | — | — | — | — |

### 结果分析

**数据量是核心瓶颈**：
- 原始 141 张图片下，三组实验 mAP@50 均在 0.25~0.30 之间，远未达到 0.70 目标
- 更令人意外的是，增大模型（n→s→m）或增加训练轮数（100→150）并未带来提升，yolo11m 反而下降到 0.25（可能过拟合）
- 合并 4 个 Roboflow 数据集后，mAP@50 跃升到 0.73，提升 143%
- 说明在数据量不足时，模型选择和数据增强的边际收益极低

**模型选择**：
- yolo11n 和 yolo11s 在重组数据集上表现几乎持平（0.73 vs 0.73），但 yolo11s 的 Recall 略高（0.88 vs 0.86）
- 推荐 yolo11s 作为生产方案：精度与 recall 均衡，且推理速度仍有优势

**早停策略有效性**：
- exp3 (yolo11n) 在 61 轮即触发早停，节约约 40% 训练时间

## 12. 错误分析与经验积累

### 错误 1：旧项目任务-数据不匹配

- **现象**：CLIP 图文检索 Recall@5 = 0.0065
- **原因**：YOLO 目标检测标注被强行用于检索任务
- **教训**：AI 项目的首要问题是"任务-数据"匹配度，模型选择其次

### 错误 2：小样本训练挑战

- **现象**：原始 141 张图片下，三轮实验 mAP@50 仅 0.25~0.30
- **原因**：单一 Roboflow 数据集样本量绝对不足，96 张训练图无法支撑高精度检测
- **对策**：合并 4 个 Roboflow 数据集，扩大数据规模和场景覆盖 → mAP@50 跃升到 0.73

### 错误 3：依赖清理

- **现象**：旧依赖 open_clip_torch、faiss 在新项目中无用
- **对策**：完整重写 requirements.txt

### 错误 4：模型下载网络问题

- **现象**：yolo11s.pt / yolo11m.pt 下载后 zip 损坏
- **原因**：GitHub release 在国内下载不稳定，大文件（>18MB）易损坏
- **对策**：train.py 增加 HF 镜像自动 fallback 机制

### 错误 5：大模型在小数据上的过拟合

- **现象**：yolo11m (150 epochs, 最大模型) mAP@50=0.25，比 yolo11n (0.30) 还差
- **原因**：141 张训练图不足以支撑 20.1M 参数模型的泛化需求，模型越大越容易在小样本上过拟合
- **教训**：大数据 + 小模型 > 小数据 + 大模型。数据量不足时优先扩充数据，而非增大模型

> 详细记录见 `docs/exec-plans/tech-debt-tracker.md`（截至 2026-10-01 共 14 条：#001~#014，
> 含后续的仓库化修复 #006~#011 与静态 Demo 的 #012~#014）

## 13. Harness 作用反思

### 上下文管理

`current-plan.md` 确保了开发进度不被丢失。每次 Agent 工作前读取，完成后更新，避免了"重新开始"的信息断层。

### 工具边界

`SECURITY.md` 明确了 Agent 的操作范围：可修改 src/、tests/、experiments/，不可删除原始数据、不可伪造指标。这些规则在实际开发中有效约束了 Agent 的行为。

### 实验记录

实验记录机制（config.yaml + metrics.json + training_curves.png）确保每组实验可追溯、可复现，满足作业"多轮实验对比"的要求。

### 错误积累

`tech-debt-tracker.md` 将开发过程中遇到的问题系统化记录，避免遗忘，也为最终报告的"错误分析"部分提供了素材。

### 交接机制

`current-plan.md` 中"给下个 Agent 的提醒"部分，使得不同时间、不同 Agent 可以无缝衔接工作。

## 14. 项目局限与改进方向

### 当前局限

1. **数据集来源单一**：全部来自 Roboflow Universe 公开数据集，场景分布不均
2. **类别有限**：仅检测使用手机的人/手机两类，未细分场景（课堂/考场/户外）
3. **无实时视频流**：当前仅支持单张图片检测，不支持摄像头实时检测
4. **exp5 未完成**：yolo11m 在重组数据集上的训练因中断未能获得结果，错过大规模模型的对比数据
5. **Web Demo 未上线**：Streamlit 应用尚未部署到公网，仅在本地可运行

### 改进方向

1. **数据层面**：自行采集国内校园场景图片并标注，增强本地场景适应性
2. **模型层面**：尝试 YOLO11l/x 更大模型或引入注意力机制头（SAHI 等）处理小目标
3. **应用层面**：接入摄像头实时视频流，支持多路监控
4. **系统层面**：加入行为统计和历史对比，生成周期性分析报告（如"本周课堂手机使用率趋势"）
5. **部署层面**：将 Web Demo 部署到局域网或公网服务器

## 15. 总结

本项目在 Agent Harness 的约束下，完成了一套基于 YOLO11 的校园手机使用检测系统。项目经历了**两个关键阶段**：

**第一阶段**用 Smart School v5 数据集训练了 3 组模型，mAP@50 仅 0.25~0.30，远未达标。
**第二阶段**合并 4 个 Roboflow 数据集后重新训练，mAP@50 跃升到 **0.73**，成功达到 0.70 质量目标。

主要收获：
1. **"数据-任务"匹配是第一性原则**：旧 CLIP 项目之所以失败，根本原因在于任务不匹配；新项目第一阶段 mAP 低，根本原因在于数据量不足
2. **大数据 + 小模型 > 小数据 + 大模型**：141 张图上 yolo11m 反而不如 yolo11n；合并数据后用 yolo11s 即达目标
3. **Agent Harness 文档体系能有效管理 AI 开发过程**：11 个文档各司其职，进度追踪、错误积累、工具边界各自发挥作用
4. **ultralytics 框架大大降低了目标检测项目的工程门槛**：从数据准备到训练到推理，代码量仅 ~800 行

与 AI Agent 协作的体会：
- Agent 在代码生成和文档编写方面效率极高，但需要明确的约束规则（AGENTS.md）引导
- Agent 可能忽略边缘情况（如国内网络下载模型失败），需要开发者实际测试后发现
- current-plan.md 的"给下个 Agent 的提醒"机制在多轮对话中保证了上下文连续性
- Harness 的最大价值不是"管住 Agent"，而是"让 Agent 的工作可追溯、可验证、可持续"
